# وب‌سایت دکتر کیانا خرسند

## وضعیت فعلی

**صفحات فاز ۶ آمادهٔ بازبینی‌اند؛ Checklist: 16 of 17 met.** تجربه‌ها، پرسش‌های متداول، تماس، حریم خصوصی و شرایط استفاده ساخته شدند. تنها مورد برآورده‌نشدهٔ این تحویل، شرط وابستگیِ پشتیبانی‌شده است: هنگام بازیابی نصب، پایان پشتیبانی ESLint 9 تأیید شد؛ توضیح و کوچک‌ترین استثنای پیشنهادی پایین آمده است. فاز ۷ شروع نشده است.

تجربه‌ها وضعیت خالی واقعی، اصول پیشنهادی رضایت/انتشار و همان سه نمونهٔ چیدمان را دارند؛ نظر، امتیاز یا نتیجهٔ درمانی جعل نشده است. FAQ دوازده پرسش در چهار گروه با ناوبری لنگری دارد؛ پاسخ‌ها در HTML سرور حاضرند و با Accordion بومی باز می‌شوند. چهار پرسش Home از همان منبع مشترک می‌آیند.

تماس شامل وضعیت صریح تلفن/واتس‌اپ/آدرس/زمان پاسخ‌گویی، پرترهٔ نمونه و هشدار برجستهٔ کمک فوری است. فرم با RHF، Controller، resolver و Zod فقط نام اختیاری، ایمیل و متن نمونه را **محلی** بررسی می‌کند. هیچ API، پیام ارسالی، رسید واقعی یا ذخیرهٔ پیام وجود ندارد. فیلدهای DOM عمداً name ندارند تا ارسال بومیِ پیش از hydration نیز مقادیر را به URL نبرد؛ نام‌های داخلی RHF حفظ شده‌اند. پیام موفقیت فقط تأیید قالب است و صریحاً می‌گوید چیزی ارسال نشده. برای بازبینی از دادهٔ آزمایشی استفاده کنید.

حریم خصوصی و شرایط استفاده دو سند خواندنی با خلاصه و فهرست لنگری هستند؛ **پیش‌نویس حقوقیِ تأییدنشده**، نه سیاست نهایی یا تضمین انطباق قانونی. پردازش فعلی فرم/جست‌وجو، ترجیح تم در مرورگر، احتمال گزارش‌های میزبان و موارد نامعلوم توضیح داده شده‌اند. حق حذف با مهلت فرضی، شرایط لغو/بازپرداخت، نشانی یا تضمین امنیت ساخته نشده است. کانال واقعی رسیدگی و جزئیات نگهداری داده پیش از فعال‌کردن خدمات باید تعیین شوند.

هر پنج صفحه metadata فارسی مستقل، breadcrumb واقعی و loading مخصوص با قالبِ یکسان و inert دارند. صفحهٔ نمونهٔ تجربه‌ها و دو سند پیش‌نویس noindex/follow هستند؛ FAQ و تماس index/follow هستند، اما سایت همچنان آمادهٔ انتشار واقعی نیست. تنها Client تازه MessageForm است و ثبت کامل به **۲۸ مورد** رسیده؛ عکس و وابستگی تازه‌ای اضافه نشده‌اند.

**Deviations needing approval — تصمیم لازم:** ESLint `9.39.5` پایان پشتیبانی دارد. نسخهٔ جاری `10.11.0` با سه افزونهٔ آخرین نسخهٔ React/JSX-a11y/import در زنجیرهٔ Next، peer سازگار اعلام‌شده ندارد. پیشنهاد حداقلی: اجازهٔ موقت برای حفظ همین ESLint صرفاً در ابزار توسعه تا انتشار ترکیب سازگار، بدون force، override، پیش‌انتشار یا حذف قواعد lint. این استثنا هنوز تأیید نشده و فایل بسته/قفل تغییر نکرده‌اند. [جزئیات رسمی و جدول peerها](SOURCES.md#phase-6--public-information-pages).

**محدودیت‌های باقی‌مانده:** نظر و اطلاعات حرفه‌ای واقعی، کانال تماس، تأیید حقوقی و بازبینی مقاله‌ها فراهم نشده‌اند؛ ثبت‌نام/رزرو/ارسال پیام، DB و SSE هنوز فعال نیستند. پیوندهای رزرو، ورود و sitemap همچنان مقصد ساخته‌شده ندارند. هدف رزرو چهارمرحله‌ای/زیر یک دقیقه سنجیده نشده است.

بازبینی پیشنهادی: `/testimonials`، `/faq`، `/contact`، `/privacy` و `/terms` در دو تم، به‌ویژه Accordion و حالت‌های بررسی فرم. تست مرورگر/شبکه/پایگاه‌داده در این محیط اجرا نشده است. منابع، پذیرش و ثبت Client در [SOURCES.md](SOURCES.md#phase-6--public-information-pages) آمده‌اند.

تا تصمیم شما دربارهٔ استثنای lint و تأیید فاز توقف می‌کنیم. مرحلهٔ بعد **فاز ۷: مخازن MongoDB، احراز هویت واقعی، نشست، SSE، اسکریپت‌های دستی و sitemap پایگاه‌داده‌ای** است؛ هیچ‌یک جلوتر از نوبت ساخته نشده‌اند.

«ادامه» پس از فاز ۰، تأیید پیشنهادهای محدود آن مرحله در نظر گرفته شد. استثناهای ابزار توسعه و بسته‌های پشتیبان همچنان در [SOURCES.md](SOURCES.md#deviations-needing-approval) ثبت‌اند؛ فایل بلااستفادهٔ `utils.ts` حذف شد. ممنوعیت عمومی وابستگی‌های منسوخ و پیش‌انتشار، خارج از همین استثناها، برقرار است.

## راه‌اندازی

Node.js دقیقاً `24.21.0`، شاخهٔ Active LTS در زمان بررسی، لازم است. نسخهٔ npm همراه این انتشار `11.19.0` است.

```bash
nvm install
nvm use
npm ci --strict-peer-deps --engine-strict --ignore-scripts
cp .env.example .env.local
```

در `.env.local`، نشانی اصلی HTTPS سایت را در `NEXT_PUBLIC_SITE_URL` قرار دهید. نشانی باید فقط origin باشد، بدون مسیر، query یا fragment. `GOOGLE_SITE_VERIFICATION` اختیاری است. تنظیمات پایگاه‌داده مطابق درخواست:

```dotenv
MONGODB_URI=mongodb://localhost:27017/
MONGODB_DB=kiana_khorsand
```

اعتبارسنجی Zod هنگام بارگذاری تنظیمات Next.js انجام می‌شود و فقط رشته‌ها را بررسی می‌کند؛ اتصال شبکه یا اتصال به MongoDB ندارد. نام متغیرهای نامعتبر گزارش می‌شود، نه مقدارشان. فایل `.env.local` در Git ثبت نمی‌شود؛ `.env.example` ثبت می‌شود.

**فقط پس از تحویل فاز ۷، روی دستگاه خودتان:** ابتدا دو اسکریپت زیر را اجرا کنید. این فایل‌ها عمداً در فاز ۰ ساخته نشده‌اند و این دستورات در محیط ساخت اجرا نشده‌اند.

```bash
node --env-file=.env.local scripts/setup-indexes.ts
node --env-file=.env.local scripts/seed.ts
```

سپس سرور توسعه را اجرا کنید؛ نسخهٔ زیرساخت فعلی به دو اسکریپت بالا یا MongoDB نیاز ندارد:

```bash
npm run dev -- --hostname 0.0.0.0
```

بررسی‌های مجاز، بدون پایگاه‌داده:

```bash
npm run typecheck
npm run lint
npm run build
npm audit
```

ساخت فعلی با موفقیت انجام شده است؛ برای فازهای بعد، اجرای build فقط وقتی مجاز است که هیچ مسیر، metadata یا sitemap هنگام ساخت به پایگاه‌داده نیاز نداشته باشد. هیچ مجموعه‌آزمونی اضافه نشده است.

## ساختار

`src/app` فقط برای مسیرهاست: گروه‌های `(public)`، `(auth)`، `(account)` و `(admin)`، به‌علاوهٔ محل رزروشدهٔ `api/live`. اجزا در `src/components/{ui,layout,motion,sections,shared}`، محتوای تایپ‌شده در `src/content`، اعتبارسنجی در `src/lib`، کد سرور در `src/server` و فونت محلی در `src/fonts` قرار می‌گیرند. `public/{brand,images}` برای دارایی‌ها و `scripts` فقط برای دو اسکریپت دستی است. پوشه‌های خالی در محیط ساخته شده‌اند؛ Git پوشهٔ خالی را ذخیره نمی‌کند. هیچ فایل نگهدارنده یا پیاده‌سازیِ زودهنگام اضافه نشده است.

`src/content/images.ts` شامل قرارداد سیزده موضوع عکاسانه با شانزده فایل عکس، به‌علاوهٔ سه گرافیک اشتراک‌گذاری است؛ در مجموع شانزده ورودی و نوزده فایل تصویر محلی داریم؛ موضوع، alt، ابعاد، نسبت و محل استفاده ثبت شده‌اند. راهنمای `public/images/README.md` پرامپت‌ها و ساختگی‌بودن تصاویر را توضیح می‌دهد. این تصاویر عکاسانهٔ تولیدشده با هوش مصنوعی‌اند، نه عکس واقعی دکتر/مراجع یا جایگزین SVG. خروجی‌های ۲۴۰۰/۱۰۸۰ پیکسلی از اصل کوچک‌تر بزرگ‌نمایی شده‌اند؛ جزئیات بومی در این اندازه ادعا نمی‌شود. در Home شش عکس موضوعی برای خدمات/دوره‌ها/مقالات و سه پرترهٔ نمونهٔ متمایز اضافه شده است. این نُه فایل از اصل بزرگ‌تر downsample شده‌اند، نه بزرگ‌نمایی؛ موضوع‌های مشترک عمداً عکس مرتبط مشترک دارند. تصاویر تازهٔ موردنیاز صفحات بعد در فاز همان صفحه می‌آیند. هیچ hotlink یا فونت Google وجود ندارد.

## محدودیت بلادرنگ

پیاده‌سازی SSE متعلق به فاز ۷ است. معماری درخواست‌شده فقط روی **یک فرایند Node.js** و برای تغییراتی که از طریق برنامه انجام می‌شوند، رویداد منتشر می‌کند. چند فرایند، چند نمونه، serverless، راه‌اندازی مجدد و ویرایش مستقیم پایگاه‌داده پوشش رویدادی مشترک ندارند. این موارد به منبع مشترک، مانند MongoDB change streams روی replica set، نیاز دارند و تا تأیید شما خارج از محدوده‌اند. سقف اتصال، heartbeat و رفتار reconnect همراه پیاده‌سازی مستند خواهند شد.

## بررسی دستی پس از تحویل صفحات

- در ابزار توسعهٔ مرورگر، cache را غیرفعال و شبکه و CPU را محدود کنید؛ در هر دو تم و هر دو وضعیت ورود، hard refresh انجام دهید. فونت، تم، سربرگ، تصاویر، اسلایدرها، اسکرول، sheetها و به‌روزرسانی زنده را از نظر جهش بررسی کنید.
- تست صفحه‌کلید، focus، reduced motion و اندازه‌های ۳۲۰، ۳۷۵، ۷۶۸، ۱۰۲۴، ۱۲۸۰، ۱۵۳۶ و ۱۹۲۰ پیکسل را انجام دهید.
- پس از انتشار: Rich Results Test، Schema Markup Validator و PageSpeed Insights را اجرا کنید؛ سپس مالکیت سایت را در Search Console تأیید و `/sitemap.xml` را در بخش Sitemaps ثبت کنید. بنیادهای SEO در فاز ۲ و sitemap پایگاه‌داده‌ای در فاز ۷ ساخته خواهند شد.
- اطلاعات حرفه‌ای، مجوز، قیمت‌ها و متن نمونه را پیش از انتشار تأیید و جایگزین کنید؛ نظرات نمونه نباید `Review` یا `AggregateRating` داشته باشند. این نشانه‌گذاری فقط برای نظر واقعی و رضایت‌داده‌شده قابل بررسی است.

هیچ بررسی مرورگری، رفتار پایگاه‌داده یا بلادرنگ، تأیید موتور جست‌وجو، آزمون بصریِ صفحات، نتیجهٔ Core Web Vitals یا تضمین فراگیرِ نبود پرش گزارش نشده است. فقط اتصال حروف لوگو و زیرنویس فارسیِ تصویر اشتراک‌گذاری، در خروجی رستریِ ابزار خارج از پروژه بازبینی شد؛ این کار آزمون رابط یا مرورگر نیست. محاسبات عددی کنتراست توکن‌ها در SOURCES ثبت شده‌اند.


## نشان تأییدشده

- انتخاب ثبت‌شده: «ب — امضای همراه»؛ هندسهٔ چهارمسیرهٔ تأییدشده حفظ شده است. برگ نیلوفر، قوس الهام‌گرفته از سای و ساختار حرف آغازین نام، هویت یک فرد را می‌سازند.
- `src/components/layout/logo.tsx` تنها محل رندر درون‌خطی لوگوی برنامه است: فرم پیش‌فرض `lockup` برای هر دو سربرگ/پابرگ؛ فرم `emblem` برای کاربرد نماد. لینک نام دسترس‌پذیر «دکتر کیانا خرسند، صفحه اصلی» دارد؛ ارتفاع SVG در موبایل ۴۰ و از ۷۶۸ پیکسل به بالا ۴۴ پیکسل است؛ هدف کلیک حداقل ۴۴ پیکسل است.
- فایل‌ها: `public/brand/logo-{light,dark,mono}.svg` و `public/brand/lockup-{light,dark,mono}.svg`. نسخهٔ روشن برای زمینهٔ روشن و نسخهٔ تیره برای زمینهٔ تیره است. تک‌رنگ از `currentColor` استفاده می‌کند: به‌صورت مستقل با تنظیم سیستم سفید/جوهری می‌شود و در چاپ جوهری است؛ برای حکاکی/چاپ از تک‌رنگ استفاده کنید. فایل SVG دانلودی مستقل است؛ برای رابط برنامه از Logo استفاده کنید، نه تزریق مجدد فایل با شناسه‌های ثابت.
- حداقل اندازه: نماد **۱۶×۱۶** پیکسل؛ ترکیب نام **۹۶ پیکسل عرض** با نسبت `336:96`. در استفادهٔ واقعی سربرگ/پابرگ ترکیب نام بزرگ‌تر است. زیر این حد از نماد استفاده کنید. هیچ تأیید مرورگریِ خوانایی در ۱۶ پیکسل ادعا نمی‌شود.
- فضای امن: حداقل **۱۲ واحد از شبکهٔ ۹۶ واحدی**، یعنی یک‌هشتم ارتفاع کادر نشان، از دورترین لبهٔ مرئی تا نوشته/لبه/عنصر دیگر؛ در نماد ۴۸ پیکسلی این فاصله ۶ پیکسل است. فاصلهٔ داخلی نام تا نماد را تغییر ندهید. کشیدن نامتقارن، چرخاندن، افزودن سایه به مسیر یا قراردادن نشان روی عکس شلوغ مجاز نیست.
- نوشتهٔ نام فقط «کیانا خرسند» است؛ عنوان دکتر و تخصص داخل لوگو نیستند. حروف از وزیرمتن رسمی، وزن ۷۵۰، با شکل‌دهی فارسی و راست‌به‌چپ به یک مسیر مرکب تبدیل شده‌اند؛ حروف دست‌کشیده یا متن وابسته به نصب فونت نیستند.
- `src/app/icon.svg` با ترجیح روشن/تیرهٔ **سیستم** تطبیق می‌یابد؛ `apple-icon.png` اندازهٔ ۱۸۰×۱۸۰ و زمینهٔ مات دارد. manifest در حالت `browser` است و قابلیت آفلاین/PWA اضافه نمی‌کند.
- تصاویر اشتراک‌گذاری پیش‌فرض `opengraph-image.png` و `twitter-image.png`، هر دو ۱۲۰۰×۶۳۰، با متن فارسیِ شکل‌دهی‌شده و مسیرشده ساخته شده‌اند. به‌دلیل نبود تضمین شکل‌دهی فارسی در مستندات بررسی‌شدهٔ next/og و پشتیبانی‌نشدن WOFF2 در ImageResponse، خروجی ثابتِ مجاز انتخاب شد؛ این تصمیم ادعای ناممکن‌بودن همهٔ روش‌های next/og نیست. این دارایی گرافیک برند است، نه جایگزین عکس‌های واقعیِ موردنیاز صفحات.

## فونت و پیشگیری از تعویض دیرهنگام

وزیرمتن رسمی نسخهٔ `33.003`، فایل متغیر WOFF2 با وزن‌های ۱۰۰ تا ۹۰۰ در `src/fonts/vazirmatn.woff2` و متن کامل مجوز OFL در `src/fonts/license.txt` قرار دارند. `next/font/local` در layout ریشه با preload، متغیر CSS، `display: "optional"` و fallback تنظیم‌شدهٔ Arial به‌کار رفته است. فایل فونت از همین سایت ارائه می‌شود؛ نام لوگو به فونت وب وابسته نیست.

**مبادلهٔ آگاهانه:** optional دورهٔ تعویض دیرهنگام ندارد؛ اگر فونت در فرصت کوتاه مرورگر نرسد، همان fallback ممکن است تا پایان آن نمایش صفحه باقی بماند. بر نمایش حتمی وزیرمتن در اولین بارگیریِ شبکهٔ بسیار کند، اولویت نداده‌ایم؛ اولویت اجتناب از تعویض دیرهنگام و تغییر شکست خطوط است. زمان دقیق و رفتار اولین paint به مرورگر وابسته است و تضمین همگانی یا اندازه‌گیری CLS انجام نشده است. در بررسی دستیِ cache-disabled/throttled، هم انتخاب فونت و هم پایداری شکست خطوط را بررسی کنید.

## تم و توکن‌ها

- `next-themes` با کلاس ریشه، پیش‌فرض سیستم، همگام‌سازی ترجیح سیستم و توقف transition هنگام تغییر تم تنظیم شده است. تنها `suppressHydrationWarning` روی `html` برای کلاس و color-scheme پیش از hydration است؛ هشدارهای بقیهٔ درخت پنهان نمی‌شوند.
- هر دو آیکن خورشید/ماه از اولین HTML در یک جای ثابت حضور دارند؛ فقط CSS ظاهر را تعیین می‌کند. `document` تنها داخل رویداد کلیک خوانده می‌شود، نه render. mounted guard یا return null وجود ندارد.
- viewport theme-color و favicon از media ترجیح سیستم پیروی می‌کنند؛ مستقل از تغییر دستی تم داخل سایت هستند. صفحه از کلاس تنظیم‌شدهٔ next-themes پیروی می‌کند.
- `src/app/globals.css`: بیست‌ودو طیف رنگی، هرکدام ۱۱ سطح از ۵۰ تا ۹۵۰؛ شانزده خانوادهٔ نام‌دار گرادیان، هرکدام نسخهٔ تأکیدی و سطح خواندنی در هر دو تم؛ نگاشت semantic به Tailwind/shadcn؛ elevation لایه‌ای، glow بنفش/سبزآبی/رز، ring فوکوس، توکن‌های زمان/فاصله و حالت‌های Button.
- نام‌های مرجع گرادیان: Aurora، Sunrise، Lagoon، Orchid، Cotton Candy، Peach Glow، Ocean، Twilight، Mint Dew، Golden Hour، Dream، Nebula، Berry، Meadow، Dusk، Coral Reef. برای متن/کنترل‌ها از جفت توکن‌های semantic استفاده کنید؛ گرادیان‌های تزئینی مجوز خودکار برای متن سفید نیستند. فقط گرادیان action برای متنِ روی دکمه محاسبه شده است.
- Button با CLI رسمی shadcn اضافه و سپس با توکن‌ها بازطراحی شده است؛ هیچ وابستگی یا نسخه‌ای تغییر نکرد. همهٔ اندازه‌های دکمه حداقل ۴۴ پیکسل و متن پایه ۱۶ پیکسل دارند. اجزای اضافه‌شده نیز از CLI رسمی آمده‌اند؛ Calendar فارسی و Chart نیز با تصمیم محدود ثبت‌شده در بالا اضافه شده‌اند.
- نتیجهٔ این بخش: TypeScript، ESLint و ساخت مستقل از DB موفق؛ audit صفر آسیب‌پذیری گزارش کرد. بررسی جامع responsive/فوکوس/تم در مرورگر و همهٔ موارد فاز ۱۱ همچنان دستی و انجام‌نشده‌اند. جدول پذیرش به‌روز و ثبت کامل مرزهای Client در [SOURCES.md](SOURCES.md#phase-6--public-information-pages) است.


## شِل مشترک و محدودیت‌های فعلی

- Header/Footer و همهٔ صفحات/بخش‌های محتوایی سروری‌اند؛ تعامل فقط در برگ‌های کوچک انجام می‌شود. Header فعلاً مهمان است؛ قرارداد Viewer برای دریافت نشست واقعی در فاز ۷ آماده است. نمونهٔ نمایشی حساب با حذف showcase برداشته شده است؛ قرارداد منوی واقعی برای فاز ۷ باقی است.
- شماره تماس، شبکه‌های اجتماعی، آدرس و شماره مجوز نامعلوم، `null` هستند؛ لینک جعلی ساخته نشده است. دکمه‌های تماس/واتساپ پس از ورود اطلاعات واقعی فعال می‌شوند. سال فارسی پابرگ یک snapshot زمان بارگذاری ماژول سرور است؛ نسخهٔ استاتیک برای تغییر سال نیاز به rebuild دارد.
- LazyMotion با `domAnimation` و MotionConfig با reduced-motion سیستم فعال است؛ ورود پنهان اولیه وجود ندارد. Sheet/Dropdown با حضور/خروج Motion، hover کارت و نشانگر تب/پیشرفت پیاده شده‌اند. transitionهای CSS دکمه و ناوبری حذف شده‌اند؛ تنها استثنای خواسته‌شده، reveal اسکرول CSS با feature-query و fallback همیشه‌مرئی است. Sonner بدون انیمیشن مستقل است.
- Embla راست‌به‌چپ با CSS اولیهٔ ۸۶٪/۵۰٪/۳۳٫۳۳٪، فلش و نقطه، autoplay ۶٫۵ ثانیه‌ای و توقف هنگام hover/focus/پنهان‌شدن صفحه/خارج‌شدن از دید/reduced-motion کار می‌کند؛ رفتار مرورگری آزموده نشده است.
- تصاویر جعبهٔ رزروشده، art direction موبایل، حالت خطا و fade فقط پس از load دارند؛ تصویر پنهان اولیه نداریم. در Home فقط Hero از eager/fetchPriority=high استفاده می‌کند و fade ندارد؛ باقی تصاویر lazy هستند. API منسوخ priority استفاده نشده است. کارت و اسکلت بدنهٔ هم‌ارتفاع دارند.
- footer و اخطارها جایگزین خدمات اورژانسی نیستند؛ هیچ وعدهٔ نتیجه، مجوز ساختگی یا Review/AggregateRating نمونه منتشر نشده است.

## امنیت و SEO فعلی

metadata و canonical مستقل فارسی برای صفحات ساخته‌شده، HTML فارسی/RTL، OG/Twitter و JSON-LD escaped برقرارند. Home شامل WebSite/Person/چهار Service است؛ About دارای AboutPage/Person و Services دارای WebPage/Person/چهار Service است. صفحات داخلی breadcrumb واقعی دارند؛ مسیر جزئیات مقاله سه سطح Home/مقالات/عنوان دارد. Article schema فقط عنوان، توضیحِ پیش‌نویس، تصویر مرتبط، زبان، موضوع و منابع واقعی را توصیف می‌کند؛ نویسنده/تاریخ/بازبین ساختگی ندارد. Course/Offer برای طرح‌های نهایی‌نشده و Review/AggregateRating برای نمونه‌ها صادر نمی‌شود. loading اسکریپت schema تکراری ندارد. صفحات فاز ۶ breadcrumb متناظر دارند؛ ContactPage بدون نشانی/تلفن فرضی اضافه شده و FAQPage/Review/AggregateRating برای این نسخه ادعا نمی‌شود.

فهرست‌های بدون query و صفحات عمومی معرفی index/follow هستند؛ گونه‌های query فهرست‌ها noindex/follow و canonical پایه دارند. هر سه مقالهٔ پیش‌نویس noindex/follow با canonical مستقل و OG/Twitter مخصوص خود هستند. تجربه‌های صرفاً نمایشی و دو سند حقوقیِ پیش‌نویس نیز noindex/follow هستند؛ FAQ و تماس وضعیت عمومی index/follow دارند. ۴۰۴ noindex است؛ slug ناشناخته با `dynamicParams=false` در مجموعهٔ fixture فعلی محدود می‌شود و `notFound()` پیش از مرز محتوایی فراخوانی می‌شود. وضعیت HTTP در مرورگر یا با درخواست زنده آزموده نشده است.

انتشار نسخهٔ دارای دادهٔ نمونه روی دامنهٔ واقعی توصیه نمی‌شود. robots مسیرهای خصوصی/ورود/API را منع می‌کند، اما جایگزین کنترل مجوز نیست. sitemap پایگاه‌داده‌ای و کنترل نشست همچنان مربوط به فاز ۷ هستند. در فاز ۷ باید `generateStaticParams` مبتنی بر fixture و `dynamicParams=false` مقاله با خواندن request-time مخزنِ محتوای مجاز جایگزین شوند؛ هرگز lookup پایگاه‌داده را داخل تولید مسیرهای build قرار ندهید.

هدرهای nosniff، Referrer-Policy و محدودیت قابلیت‌ها سراسری‌اند. HSTS بدون includeSubDomains/preload فقط وقتی `x-forwarded-proto: https` از پراکسی برسد ارسال می‌شود؛ پراکسی انتشار باید این هدر را بازنویسی و معتبر کند. X-Frame-Options و CSP فقط با `frame-ancestors 'none'` روی hostname اصلی تنظیم‌شده فعال‌اند؛ میزبان متفاوتِ پیش‌نمایش برای نمایش iframe مسدود نمی‌شود. این سیاست یک CSP کاملِ محدودکنندهٔ اسکریپت نیست. هدرها در مرورگر/محیط انتشار بررسی نشده‌اند.

**SEO checklist: met برای پیاده‌سازی صفحات فاز ۶ از روی کد.** عنوان/توضیح فارسی، canonical، OG/Twitter اختصاصی مقاله، یک h1، headingهای منطقی، alt/ابعاد، لینک‌های قابل‌خزش، breadcrumb و schema متناسب وجود دارند. این به معنی آمادگی انتشار یا واجدشرایط‌بودن نتیجهٔ غنی نیست؛ نویسندگی/بازبینی حرفه‌ای، انتشار مقاله‌ها، دورهٔ واقعی، تأیید اسناد حقوقی و اطلاعات تماس، sitemap DB و کنترل انتشار همچنان تکمیل نشده‌اند.
**Zero-flicker check: met از نظر راهبرد کد، نه تأیید بصری.** تم پیش‌ازpaint، فونت optional، هدر ثابت، نسبت تصاویر، RTL و فضای نوار موبایل حفظ شده‌اند. fallbackهای صریح از همان حالت URL/slug حل‌شده استفاده می‌کنند؛ Home دیگر fallback ارثی صفحات داخلی نیست. تا حل پارامترها نمایش فوری اسکلت تضمین نمی‌شود؛ با دادهٔ محلی ممکن است fallback اصلاً دیده نشود. فرم جست‌وجو مقدار `defaultValue` سروری دارد و MessageForm با مقدارهای کنترل‌شدهٔ خالی از سرور شروع می‌شود. هر دو از useId و فضای رزروشدهٔ پیام استفاده می‌کنند؛ داده‌ای پس از اولین mount به فرم تزریق نمی‌شود. هر پنج مسیر فاز ۶ loading مستقل با همان قالب دارند. پیام وضعیت تماس توضیح ثابت و عنوان کوتاهِ هم‌جایگاه دارد؛ خطاهای فیلدها فضای رزروشده دارند. پاسخ‌های FAQ با forceMount در HTML هستند و CSS حالت بسته را از ابتدا پنهان می‌کند، بدون فلش همهٔ جواب‌ها هنگام hydration. جست‌وجوی تعاملی و تغییر موضوع/ترتیب بدون scroll اجباری انجام می‌شوند؛ لنگرها و صفحه‌بندی از پیمایش بومی استفاده می‌کنند. ابعاد کارت‌ها از CSS می‌آیند، نه خواندن viewport. نتیجهٔ خواسته‌شدهٔ فیلتر می‌تواند ارتفاع متفاوتی داشته باشد؛ این تغییر آگاهانهٔ محتواست، نه تضمین اندازهٔ یکسانِ نتیجه‌های مختلف.

### بازبینی دستیِ باقی‌مانده

با cache غیرفعال و شبکهٔ کند، hard refresh صفحات را در دو تم و عرض‌های ۳۲۰ تا ۱۹۲۰+ بررسی کنید: فونت/شکست خطوط، کادر عکس، هدر، footer و نوار رزرو. سپس URL جست‌وجوی غیرخالی را مستقیماً باز کنید و بازگشت/جلو، نتیجهٔ خالی، پارامتر نامعتبر، حفظ ورودی، focus و لنگرها را بررسی کنید. در تماس فقط دادهٔ آزمایشی وارد کنید؛ وضعیت «قالب معتبر» نباید به معنی ارسال برداشت شود. رفتار بدون جاوااسکریپت/پیش از hydration و نبود مقادیر فرم در درخواست نیز باید روی دستگاه خودتان بررسی شود. نبود نمایش گذرای Home/مقالهٔ اشتباه و باقی‌ماندن محتوای قبلی هنگام انتظار باید دستی تأیید شود. پس از اتصال auth در فاز ۷، با نشست واقعی واردشده و مهمان تکرار کنید؛ نشست واقعی فعلاً وجود ندارد. هیچ ادعای اجرای این بررسی‌ها یا اندازه‌گیری CLS/Core Web Vitals نداریم.

آخرین بررسی‌های مجاز: TypeScript، ESLint و build مستقل از DB موفق؛ audit صفر آسیب‌پذیری. هیچ تست، مرورگر، اتصال پایگاه‌داده، handler زنده یا ابزار SEO اجرا نشده است.


## اجزای پایهٔ تأییدشده

Calendar، Chart و دیگر primitiveهای لازم فاز ۲ حفظ شده‌اند، اما نمونه‌های نمایشی آن‌ها حذف شده‌اند و در Home مونت نمی‌شوند. نیازمندی‌های بسته‌ها و استثنای محدود تقویم تغییر نکرده‌اند. فرم آزمایشی فاز ۲ حذف شده است؛ فاز ۶ یک MessageForm و messageSchema تازه برای نمونهٔ واقعی صفحهٔ تماس دارد. Home فرم ارسال اطلاعات ندارد. شِل، عکس‌ها، اسلایدر و primitiveهای موردنیاز صفحه از پایهٔ مشترک استفاده می‌کنند. ثبت فعلی شامل **۲۸ مرز Client** (دو ماژول context) است؛ پنج مرز نمایش موقت در فاز ۳ حذف، SearchForm در فاز ۵ و MessageForm در فاز ۶ اضافه شدند.

## محتوای Home و بازبینی

- دادهٔ تایپ‌شدهٔ Home در `src/content/home.ts` و داده‌های مشترک در `src/content/services.ts`، `src/content/articles.ts` و `src/content/courses.ts`، بخش‌های سروری در `components/sections/home` و کارت‌های تکرارشونده در `components/shared` هستند. slugها لاتین و یکتا هستند؛ سه مسیر جزئیات مقاله ساخته شده و کارت دوره‌ها به لنگر واقعی طرح همان دوره می‌رود.
- فقط Hero و دعوت پایانی عکس تمام‌عرض دارند؛ بخش‌های دیگر SectionSurface با سطح‌های متفاوت و عکس داخل کارت هستند. نسخهٔ موبایل عکس‌های تمام‌عرض از فایل crop جدا استفاده می‌کند. همهٔ نوشته‌ها، فلش‌ها، تاریخ/عددهای نمایشی و سلسله‌مراتب عمل‌ها فارسی/RTL هستند.
- CTA اصلی در Hero، بعد از خدمات، دعوت پایانی و نوار ثابت موبایل است. عمل‌های دیدن مطالب/آشنایی با من آرام‌ترند. هیچ ادعای تکمیل رزرو یا نمایش زمان واقعی وجود ندارد.
- متن آموزشی فعلی توصیهٔ تشخیصی یا وعدهٔ نتیجه نیست. در Home schema Article/Course برای کارت‌های نمونه نداریم؛ جزئیات مقاله Article محدود و صادقانه دارد و Course/Review نمونه صادر نمی‌شود. FAQ و تجربه‌ها اکنون از content/questions.ts و content/stories.ts مشترک استفاده می‌کنند. Home breadcrumb ساختگی ندارد؛ breadcrumb واقعی About/Services در فاز ۴ اضافه شده است.
- در مرورگرِ خودتان عرض‌های ۳۲۰ تا ۱۹۲۰+، دو تم، هدر/نوار رزرو، حاشیهٔ امن، portrait crop، carousel swipe/keyboard/pause و FAQ focus را بازبینی کنید. cache-disabled/throttled hard refresh همچنان لازم است؛ در این محیط هیچ‌کدام اجرا نشده‌اند.


## قرارداد URL فهرست‌ها

هر دو مسیر `/articles` و `/courses` از `q` (تا ۸۰ نویسه)، `category` (کلید موضوع)، `sort` (`featured` یا `title`) و `page` (عدد صحیح ۱ تا ۱۰۰۰) استفاده می‌کنند. جست‌وجو عنوان، توضیح و نام موضوع را با یکسان‌سازی ی/ک عربی و فارسی، اعراب و نیم‌فاصله بررسی می‌کند؛ همهٔ واژه‌های عبارت باید وجود داشته باشند. فیلتر/مرتب‌سازی/برش صفحه روی سرور انجام می‌شود. تغییر موضوع، ترتیب یا عبارت صفحه را به ۱ برمی‌گرداند؛ شمارهٔ خارج از تعداد صفحات به آخرین صفحهٔ موجود محدود می‌شود. فرم GET بدون JavaScript نیز قابل‌ارسال است؛ RHF/Zod رفتار تعاملی و اعتبارسنجی همسان را اضافه می‌کنند. هیچ API یا query پایگاه‌داده در این فاز وجود ندارد.

نمونهٔ بازبینی دستی: `/articles?q=استرس`، `/articles?category=care&sort=title`، `/courses?category=communication`، `/articles?q=عبارتناموجود` و `/articles?page=نامعتبر`. این نمونه‌ها مسیر بررسی‌اند، نه گزارش اجرای آزمون.


## الزامات پیش از فعال‌کردن خدمات

- فاز ۷: با فعال‌شدن نشست و حساب، Privacy باید نوع/کاربرد/عمر کوکی‌ها و دریافت دادهٔ حساب را بر اساس تنظیم واقعی توضیح دهد؛ متن فعلی «حساب غیرفعال» دیگر نباید باقی بماند. هیچ تغییر DB را در محیط ساخت اجرا نکنید.
- فاز ۸: پیش از وصل‌کردن پیام/رزرو، اعتبارسنجی سرور و کنترل دسترسی/نرخ، کانال پاسخ‌گویی، رضایت و هدف دریافت داده، نگهداری/حذف/پشتیبان و شرایط جلسه را مشخص کنید. فرم فعلی نه ذخیره دارد و نه درخواست را ارسال می‌کند؛ نام‌های DOM و روش ارسال باید همراه با endpoint امن بازنگری شوند، نه جداگانه.
- پیام موفقِ ارسال فقط پس از نتیجهٔ واقعی مجاز است. باقی‌ماندن پیام نمونهٔ «فقط بررسی» بعد از اتصال backend نیز نادرست خواهد بود؛ FAQ/Privacy/Terms/Home باید هم‌زمان به‌روز شوند.
- تأیید طراحی، جای تأیید حرفه‌ایِ مقاله‌ها، رضایت انتشار نظر یا بازبینی حقوقی اسناد را نمی‌گیرد. تاریخ اجرای سند نهایی، اطلاعات مسئول رسیدگی و داده‌های میزبانی هنوز نامعلوم‌اند.
- ابزارها از snapshot حذف شده بودند؛ Node تأییدشده با SHA256 رسمی بازیابی و `npm ci --strict-peer-deps --engine-strict --ignore-scripts` اجرا شد. اجازهٔ اجرای postinstall جدید داده نشده؛ هشدار EOL ابزار lint، با وجود audit صفر، نیاز به تصمیم مستقل دارد.
