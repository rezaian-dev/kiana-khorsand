# وب‌سایت دکتر کیانا خرسند

## وضعیت فعلی

**فاز ۴، دربارهٔ من و خدمات، برای بازبینی تحویل شده است؛ Checklist: 14 of 14 met در محدودهٔ این فاز.** پیام «ادامه» تأیید فاز ۳ و مجوز ساخت فقط این دو صفحه در نظر گرفته شد. مسیرهای `/`، `/about` و `/services` اکنون ساخته شده‌اند؛ نمایش موقت سیستم طراحی همچنان حذف‌شده باقی است.

دربارهٔ من شامل معرفی و پرترهٔ قاب‌دار، اصول همکاری، وضعیت روشن اطلاعات حرفه‌ای، مسیر همکاری و دعوت به رزرو است. خدمات شامل ناوبری چهارلنگری، معرفی تفصیلی مشاورهٔ فردی/زوج‌ها/خانواده/آنلاین، عکس‌های مرتبط، آمادگی پیش از جلسه و دعوت پایانی است. همهٔ بخش‌ها سروری‌اند؛ هیچ مرز Client جدیدی اضافه نشده و ثبت کامل همچنان **۲۶ مورد** است.

هر صفحه loading مخصوص خود با محتوای یکسان، هندسهٔ یکسان، `inert` و پیام وضعیت دارد. نوار رزرو موبایل با safe area در هر سه صفحه دیده می‌شود؛ فاصلهٔ انتهای پابرگ فقط روی صفحات دارای این نوار اعمال می‌شود، نه ۴۰۴. دادهٔ خدمات از Home به `src/content/services.ts` منتقل شده و هر دو صفحه از همان منبع استفاده می‌کنند.

**محدودیت روشن:** این تحویل صفحات معرفی است، نه رزرو عملیاتی. رزرو، صفحات محتوایی بعدی، تماس و حساب هنوز ساخته نشده‌اند و لینک‌هایشان فعلاً به ۴۰۴ می‌رسند. هدف رزرو چهارمرحله‌ای/زیر یک دقیقه هنوز سنجیده یا محقق نشده؛ اتصال واقعی به فاز ۸ تعلق دارد. تماس و مجوز نامعلوم، `null` باقی مانده‌اند. مدرک، دانشگاه، سال‌های سابقه، روش درمان، تعرفه، مدت یا ظرفیت پذیرش فرضی درج نشده است. متن حرفه‌ای و جزئیات همکاری پیش از انتشار نیاز به تأیید صاحب سایت دارند.

تصاویر نمونه‌های هوش مصنوعی‌اند، نه عکس واقعی دکتر یا مراجعان؛ کنار تصاویر و در متن صفحه اعلام شده است. فاز ۴ هیچ تصویر یا وابستگی جدیدی ندارد. نظر یا نتیجهٔ درمان جعل نشده؛ سه کارت Home همچنان نمونهٔ چیدمان‌اند و هیچ Review/AggregateRating ندارند. دو استثنای محدود وابستگی فاز ۲ بدون تغییر باقی‌اند.

**Deviations needing approval: مورد تازه‌ای ندارد.** پذیرش، منابع رسمی و ثبت کامل Client در [SOURCES.md](SOURCES.md#phase-4--about-and-services) است. برای بازبینی، `/about` و `/services` و پیوندهای آن‌ها از Home را در هر دو تم ببینید؛ ناوبری لنگری خدمات، متن معرفی و نوار پایین موبایل را بررسی کنید.

تا تأیید و «ادامه» توقف می‌کنیم. مرحلهٔ بعد **فاز ۵: مقالات، جزئیات مقاله و دوره‌ها** است؛ صفحات بعدی، auth، DB و SSE جلوتر از نوبت ساخته نمی‌شوند.

«ادامه» پس از فاز ۰، تأیید پیشنهادهای محدود آن مرحله در نظر گرفته شد. استثناهای ابزار توسعه و بسته‌های پشتیبان همچنان در [SOURCES.md](SOURCES.md#deviations-needing-approval) ثبت‌اند؛ فایل بلااستفادهٔ `utils.ts` حذف شد. ممنوعیت عمومی وابستگی‌های منسوخ و پیش‌انتشار، خارج از همین استثناها، برقرار است.

## راه‌اندازی

Node.js دقیقاً `24.21.0`، شاخهٔ Active LTS در زمان بررسی، لازم است. نسخهٔ npm همراه این انتشار `11.19.0` است.

```bash
nvm install
nvm use
npm ci --strict-peer-deps --engine-strict
cp .env.example .env.local
```

در `.env.local`، نشانی اصلی HTTPS سایت را در `NEXT_PUBLIC_SITE_URL` قرار دهید. نشانی باید فقط origin باشد، بدون مسیر، query یا fragment. `GOOGLE_SITE_VERIFICATION` اختیاری است. تنظیمات پایگاه‌داده مطابق درخواست:

```dotenv
MONGODB_URI=mongodb://localhost:27017/
MONGODB_DB=kiana_khorsand
```

اعتبارسنجی Zod هنگام بارگذاری تنظیمات Next.js انجام می‌شود و فقط رشته‌ها را بررسی می‌کند؛ اتصال شبکه یا اتصال به MongoDB ندارد. نام متغیرهای نامعتبر گزارش می‌شود، نه مقدارشان. فایل `.env.local` در Git ثبت نمی‌شود؛ `.env.example` ثبت می‌شود.

**فقط پس از تحویل فاز ۷، روی دستگاه خودتان:** ابتدا دو اسکریپت زیر را اجرا کنید. این فایل‌ها عمداً در فاز ۰ ساخته نشده‌اند و این دستورات در محیط ساخت اجرا نشده‌اند.

```bash
node --env-file=.env.local scripts/setup-indexes.ts
node --env-file=.env.local scripts/seed.ts
```

سپس سرور توسعه را اجرا کنید؛ نسخهٔ زیرساخت فعلی به دو اسکریپت بالا یا MongoDB نیاز ندارد:

```bash
npm run dev -- --hostname 0.0.0.0
```

بررسی‌های مجاز، بدون پایگاه‌داده:

```bash
npm run typecheck
npm run lint
npm run build
npm audit
```

ساخت فعلی با موفقیت انجام شده است؛ برای فازهای بعد، اجرای build فقط وقتی مجاز است که هیچ مسیر، metadata یا sitemap هنگام ساخت به پایگاه‌داده نیاز نداشته باشد. هیچ مجموعه‌آزمونی اضافه نشده است.

## ساختار

`src/app` فقط برای مسیرهاست: گروه‌های `(public)`، `(auth)`، `(account)` و `(admin)`، به‌علاوهٔ محل رزروشدهٔ `api/live`. اجزا در `src/components/{ui,layout,motion,sections,shared}`، محتوای تایپ‌شده در `src/content`، اعتبارسنجی در `src/lib`، کد سرور در `src/server` و فونت محلی در `src/fonts` قرار می‌گیرند. `public/{brand,images}` برای دارایی‌ها و `scripts` فقط برای دو اسکریپت دستی است. پوشه‌های خالی در محیط ساخته شده‌اند؛ Git پوشهٔ خالی را ذخیره نمی‌کند. هیچ فایل نگهدارنده یا پیاده‌سازیِ زودهنگام اضافه نشده است.

`src/content/images.ts` شامل قرارداد و سیزده موضوع تصویری محلی با شانزده فایل نهایی است؛ موضوع، alt، ابعاد، نسبت و محل استفاده ثبت شده‌اند. راهنمای `public/images/README.md` پرامپت‌ها و ساختگی‌بودن تصاویر را توضیح می‌دهد. این تصاویر عکاسانهٔ تولیدشده با هوش مصنوعی‌اند، نه عکس واقعی دکتر/مراجع یا جایگزین SVG. خروجی‌های ۲۴۰۰/۱۰۸۰ پیکسلی از اصل کوچک‌تر بزرگ‌نمایی شده‌اند؛ جزئیات بومی در این اندازه ادعا نمی‌شود. در Home شش عکس موضوعی برای خدمات/دوره‌ها/مقالات و سه پرترهٔ نمونهٔ متمایز اضافه شده است. این نُه فایل از اصل بزرگ‌تر downsample شده‌اند، نه بزرگ‌نمایی؛ موضوع‌های مشترک عمداً عکس مرتبط مشترک دارند. تصاویر تازهٔ موردنیاز صفحات بعد در فاز همان صفحه می‌آیند. هیچ hotlink یا فونت Google وجود ندارد.

## محدودیت بلادرنگ

پیاده‌سازی SSE متعلق به فاز ۷ است. معماری درخواست‌شده فقط روی **یک فرایند Node.js** و برای تغییراتی که از طریق برنامه انجام می‌شوند، رویداد منتشر می‌کند. چند فرایند، چند نمونه، serverless، راه‌اندازی مجدد و ویرایش مستقیم پایگاه‌داده پوشش رویدادی مشترک ندارند. این موارد به منبع مشترک، مانند MongoDB change streams روی replica set، نیاز دارند و تا تأیید شما خارج از محدوده‌اند. سقف اتصال، heartbeat و رفتار reconnect همراه پیاده‌سازی مستند خواهند شد.

## بررسی دستی پس از تحویل صفحات

- در ابزار توسعهٔ مرورگر، cache را غیرفعال و شبکه و CPU را محدود کنید؛ در هر دو تم و هر دو وضعیت ورود، hard refresh انجام دهید. فونت، تم، سربرگ، تصاویر، اسلایدرها، اسکرول، sheetها و به‌روزرسانی زنده را از نظر جهش بررسی کنید.
- تست صفحه‌کلید، focus، reduced motion و اندازه‌های ۳۲۰، ۳۷۵، ۷۶۸، ۱۰۲۴، ۱۲۸۰، ۱۵۳۶ و ۱۹۲۰ پیکسل را انجام دهید.
- پس از انتشار: Rich Results Test، Schema Markup Validator و PageSpeed Insights را اجرا کنید؛ سپس مالکیت سایت را در Search Console تأیید و `/sitemap.xml` را در بخش Sitemaps ثبت کنید. بنیادهای SEO در فاز ۲ و sitemap پایگاه‌داده‌ای در فاز ۷ ساخته خواهند شد.
- اطلاعات حرفه‌ای، مجوز، قیمت‌ها و متن نمونه را پیش از انتشار تأیید و جایگزین کنید؛ نظرات نمونه نباید `Review` یا `AggregateRating` داشته باشند. این نشانه‌گذاری فقط برای نظر واقعی و رضایت‌داده‌شده قابل بررسی است.

هیچ بررسی مرورگری، رفتار پایگاه‌داده یا بلادرنگ، تأیید موتور جست‌وجو، آزمون بصریِ صفحات، نتیجهٔ Core Web Vitals یا تضمین فراگیرِ نبود پرش گزارش نشده است. فقط اتصال حروف لوگو و زیرنویس فارسیِ تصویر اشتراک‌گذاری، در خروجی رستریِ ابزار خارج از پروژه بازبینی شد؛ این کار آزمون رابط یا مرورگر نیست. محاسبات عددی کنتراست توکن‌ها در SOURCES ثبت شده‌اند.


## نشان تأییدشده

- انتخاب ثبت‌شده: «ب — امضای همراه»؛ هندسهٔ چهارمسیرهٔ تأییدشده حفظ شده است. برگ نیلوفر، قوس الهام‌گرفته از سای و ساختار حرف آغازین نام، هویت یک فرد را می‌سازند.
- `src/components/layout/logo.tsx` تنها محل رندر درون‌خطی لوگوی برنامه است: فرم پیش‌فرض `lockup` برای هر دو سربرگ/پابرگ؛ فرم `emblem` برای کاربرد نماد. لینک نام دسترس‌پذیر «دکتر کیانا خرسند، صفحه اصلی» دارد؛ ارتفاع SVG در موبایل ۴۰ و از ۷۶۸ پیکسل به بالا ۴۴ پیکسل است؛ هدف کلیک حداقل ۴۴ پیکسل است.
- فایل‌ها: `public/brand/logo-{light,dark,mono}.svg` و `public/brand/lockup-{light,dark,mono}.svg`. نسخهٔ روشن برای زمینهٔ روشن و نسخهٔ تیره برای زمینهٔ تیره است. تک‌رنگ از `currentColor` استفاده می‌کند: به‌صورت مستقل با تنظیم سیستم سفید/جوهری می‌شود و در چاپ جوهری است؛ برای حکاکی/چاپ از تک‌رنگ استفاده کنید. فایل SVG دانلودی مستقل است؛ برای رابط برنامه از Logo استفاده کنید، نه تزریق مجدد فایل با شناسه‌های ثابت.
- حداقل اندازه: نماد **۱۶×۱۶** پیکسل؛ ترکیب نام **۹۶ پیکسل عرض** با نسبت `336:96`. در استفادهٔ واقعی سربرگ/پابرگ ترکیب نام بزرگ‌تر است. زیر این حد از نماد استفاده کنید. هیچ تأیید مرورگریِ خوانایی در ۱۶ پیکسل ادعا نمی‌شود.
- فضای امن: حداقل **۱۲ واحد از شبکهٔ ۹۶ واحدی**، یعنی یک‌هشتم ارتفاع کادر نشان، از دورترین لبهٔ مرئی تا نوشته/لبه/عنصر دیگر؛ در نماد ۴۸ پیکسلی این فاصله ۶ پیکسل است. فاصلهٔ داخلی نام تا نماد را تغییر ندهید. کشیدن نامتقارن، چرخاندن، افزودن سایه به مسیر یا قراردادن نشان روی عکس شلوغ مجاز نیست.
- نوشتهٔ نام فقط «کیانا خرسند» است؛ عنوان دکتر و تخصص داخل لوگو نیستند. حروف از وزیرمتن رسمی، وزن ۷۵۰، با شکل‌دهی فارسی و راست‌به‌چپ به یک مسیر مرکب تبدیل شده‌اند؛ حروف دست‌کشیده یا متن وابسته به نصب فونت نیستند.
- `src/app/icon.svg` با ترجیح روشن/تیرهٔ **سیستم** تطبیق می‌یابد؛ `apple-icon.png` اندازهٔ ۱۸۰×۱۸۰ و زمینهٔ مات دارد. manifest در حالت `browser` است و قابلیت آفلاین/PWA اضافه نمی‌کند.
- تصاویر اشتراک‌گذاری پیش‌فرض `opengraph-image.png` و `twitter-image.png`، هر دو ۱۲۰۰×۶۳۰، با متن فارسیِ شکل‌دهی‌شده و مسیرشده ساخته شده‌اند. به‌دلیل نبود تضمین شکل‌دهی فارسی در مستندات بررسی‌شدهٔ next/og و پشتیبانی‌نشدن WOFF2 در ImageResponse، خروجی ثابتِ مجاز انتخاب شد؛ این تصمیم ادعای ناممکن‌بودن همهٔ روش‌های next/og نیست. این دارایی گرافیک برند است، نه جایگزین عکس‌های واقعیِ موردنیاز صفحات.

## فونت و پیشگیری از تعویض دیرهنگام

وزیرمتن رسمی نسخهٔ `33.003`، فایل متغیر WOFF2 با وزن‌های ۱۰۰ تا ۹۰۰ در `src/fonts/vazirmatn.woff2` و متن کامل مجوز OFL در `src/fonts/license.txt` قرار دارند. `next/font/local` در layout ریشه با preload، متغیر CSS، `display: "optional"` و fallback تنظیم‌شدهٔ Arial به‌کار رفته است. فایل فونت از همین سایت ارائه می‌شود؛ نام لوگو به فونت وب وابسته نیست.

**مبادلهٔ آگاهانه:** optional دورهٔ تعویض دیرهنگام ندارد؛ اگر فونت در فرصت کوتاه مرورگر نرسد، همان fallback ممکن است تا پایان آن نمایش صفحه باقی بماند. بر نمایش حتمی وزیرمتن در اولین بارگیریِ شبکهٔ بسیار کند، اولویت نداده‌ایم؛ اولویت اجتناب از تعویض دیرهنگام و تغییر شکست خطوط است. زمان دقیق و رفتار اولین paint به مرورگر وابسته است و تضمین همگانی یا اندازه‌گیری CLS انجام نشده است. در بررسی دستیِ cache-disabled/throttled، هم انتخاب فونت و هم پایداری شکست خطوط را بررسی کنید.

## تم و توکن‌ها

- `next-themes` با کلاس ریشه، پیش‌فرض سیستم، همگام‌سازی ترجیح سیستم و توقف transition هنگام تغییر تم تنظیم شده است. تنها `suppressHydrationWarning` روی `html` برای کلاس و color-scheme پیش از hydration است؛ هشدارهای بقیهٔ درخت پنهان نمی‌شوند.
- هر دو آیکن خورشید/ماه از اولین HTML در یک جای ثابت حضور دارند؛ فقط CSS ظاهر را تعیین می‌کند. `document` تنها داخل رویداد کلیک خوانده می‌شود، نه render. mounted guard یا return null وجود ندارد.
- viewport theme-color و favicon از media ترجیح سیستم پیروی می‌کنند؛ مستقل از تغییر دستی تم داخل سایت هستند. صفحه از کلاس تنظیم‌شدهٔ next-themes پیروی می‌کند.
- `src/app/globals.css`: بیست‌ودو طیف رنگی، هرکدام ۱۱ سطح از ۵۰ تا ۹۵۰؛ شانزده خانوادهٔ نام‌دار گرادیان، هرکدام نسخهٔ تأکیدی و سطح خواندنی در هر دو تم؛ نگاشت semantic به Tailwind/shadcn؛ elevation لایه‌ای، glow بنفش/سبزآبی/رز، ring فوکوس، توکن‌های زمان/فاصله و حالت‌های Button.
- نام‌های مرجع گرادیان: Aurora، Sunrise، Lagoon، Orchid، Cotton Candy، Peach Glow، Ocean، Twilight، Mint Dew، Golden Hour، Dream، Nebula، Berry، Meadow، Dusk، Coral Reef. برای متن/کنترل‌ها از جفت توکن‌های semantic استفاده کنید؛ گرادیان‌های تزئینی مجوز خودکار برای متن سفید نیستند. فقط گرادیان action برای متنِ روی دکمه محاسبه شده است.
- Button با CLI رسمی shadcn اضافه و سپس با توکن‌ها بازطراحی شده است؛ هیچ وابستگی یا نسخه‌ای تغییر نکرد. همهٔ اندازه‌های دکمه حداقل ۴۴ پیکسل و متن پایه ۱۶ پیکسل دارند. اجزای اضافه‌شده نیز از CLI رسمی آمده‌اند؛ Calendar فارسی و Chart نیز با تصمیم محدود ثبت‌شده در بالا اضافه شده‌اند.
- نتیجهٔ این بخش: TypeScript، ESLint و ساخت مستقل از DB موفق؛ audit صفر آسیب‌پذیری گزارش کرد. بررسی جامع responsive/فوکوس/تم در مرورگر و همهٔ موارد فاز ۱۱ همچنان دستی و انجام‌نشده‌اند. جدول پذیرش به‌روز و ثبت کامل مرزهای Client در [SOURCES.md](SOURCES.md#phase-4--about-and-services) است.


## شِل مشترک و محدودیت‌های فعلی

- Header/Footer/Home/About/Services و بخش‌ها سروری‌اند؛ تعامل فقط در برگ‌های کوچک انجام می‌شود. Header فعلاً مهمان است؛ قرارداد Viewer برای دریافت نشست واقعی در فاز ۷ آماده است. نمونهٔ نمایشی حساب با حذف showcase برداشته شده است؛ قرارداد منوی واقعی برای فاز ۷ باقی است.
- شماره تماس، شبکه‌های اجتماعی، آدرس و شماره مجوز نامعلوم، `null` هستند؛ لینک جعلی ساخته نشده است. دکمه‌های تماس/واتساپ پس از ورود اطلاعات واقعی فعال می‌شوند. سال فارسی پابرگ یک snapshot زمان بارگذاری ماژول سرور است؛ نسخهٔ استاتیک برای تغییر سال نیاز به rebuild دارد.
- LazyMotion با `domAnimation` و MotionConfig با reduced-motion سیستم فعال است؛ ورود پنهان اولیه وجود ندارد. Sheet/Dropdown با حضور/خروج Motion، hover کارت و نشانگر تب/پیشرفت پیاده شده‌اند. transitionهای CSS دکمه و ناوبری حذف شده‌اند؛ تنها استثنای خواسته‌شده، reveal اسکرول CSS با feature-query و fallback همیشه‌مرئی است. Sonner بدون انیمیشن مستقل است.
- Embla راست‌به‌چپ با CSS اولیهٔ ۸۶٪/۵۰٪/۳۳٫۳۳٪، فلش و نقطه، autoplay ۶٫۵ ثانیه‌ای و توقف هنگام hover/focus/پنهان‌شدن صفحه/خارج‌شدن از دید/reduced-motion کار می‌کند؛ رفتار مرورگری آزموده نشده است.
- تصاویر جعبهٔ رزروشده، art direction موبایل، حالت خطا و fade فقط پس از load دارند؛ تصویر پنهان اولیه نداریم. در Home فقط Hero از eager/fetchPriority=high استفاده می‌کند و fade ندارد؛ باقی تصاویر lazy هستند. API منسوخ priority استفاده نشده است. کارت و اسکلت بدنهٔ هم‌ارتفاع دارند.
- footer و اخطارها جایگزین خدمات اورژانسی نیستند؛ هیچ وعدهٔ نتیجه، مجوز ساختگی یا Review/AggregateRating نمونه منتشر نشده است.

## امنیت و SEO فعلی

metadata و canonical مستقل فارسی برای Home، About و Services، HTML فارسی/RTL، OG/Twitter و JSON-LD escaped برقرارند. Home شامل WebSite/Person/چهار Service است؛ About دارای AboutPage/Person و Services دارای WebPage/Person/چهار Service است. دو صفحهٔ داخلی BreadcrumbList مطابق مسیر قابل‌مشاهدهٔ «صفحه اصلی ← صفحهٔ فعلی» دارند. شناسهٔ Person و خدمات میان صفحه‌ها یکسان است؛ نشانی شخص به About و نشانی خدمات به لنگر واقعی در Services اشاره دارد. تصویر ساختگی به Person نسبت داده نشده است. loading اسکریپت schema تکراری ندارد.

هر سه صفحه index/follow هستند؛ ۴۰۴ metadata اختصاصی/noindex دارد. انتشار نسخهٔ دارای دادهٔ نمونه روی دامنهٔ واقعی توصیه نمی‌شود. BreadcrumbList برای fragmentها ساخته نشده است؛ robots مسیرهای خصوصی/ورود/API را منع می‌کند، اما جایگزین کنترل مجوز نیست. sitemap پایگاه‌داده‌ای و کنترل نشست همچنان به فاز ۷ تعلق دارند.

هدرهای nosniff، Referrer-Policy و محدودیت قابلیت‌ها سراسری‌اند. HSTS بدون includeSubDomains/preload فقط وقتی `x-forwarded-proto: https` از پراکسی برسد ارسال می‌شود؛ پراکسی انتشار باید این هدر را بازنویسی و معتبر کند. X-Frame-Options و CSP فقط با `frame-ancestors 'none'` روی hostname اصلی تنظیم‌شده فعال‌اند؛ میزبان متفاوتِ پیش‌نمایش برای نمایش iframe مسدود نمی‌شود. این سیاست یک CSP کاملِ محدودکنندهٔ اسکریپت نیست. هدرها در مرورگر/محیط انتشار بررسی نشده‌اند.

**SEO checklist: met برای پیاده‌سازی سه صفحه از روی کد.** عنوان/توضیح مستقل، canonical، OG/Twitter، یک h1 در هر صفحه، headingهای منطقی، alt/ابعاد، لینک‌های قابل‌خزش، breadcrumb داخلی و schema متناسب وجود دارند. این به معنی آمادگی انتشار یا تأیید موتور جست‌وجو نیست؛ sitemap DB، صفحات مقصد باقی‌مانده و کنترل انتشار در فاز خودشان هستند.
**Zero-flicker check: met از نظر راهبرد کد، نه تأیید بصری.** تم پیش‌ازpaint و فونت optional حفظ شده‌اند؛ هر صفحه و loading خودش هندسه و محتوای یکسان دارند. About/Services مرز loading نزدیک به مسیر دارند؛ fallback گروه عمومی همچنان مخصوص محتوای Home است و در layout عمومی کار async/DB جدیدی اضافه نشده است. عکس‌ها نسبت رزروشده دارند، فقط پس از load fade می‌شوند و در ابتدا پنهان نیستند. تم، چیدمان و نوار موبایل از ابتدا با CSS انتخاب می‌شوند؛ هیچ خواندن اندازهٔ viewport یا mounted guard اضافه نشده است. Home همچنان هندسهٔ اولیهٔ کاروسل و snapshotهای SSR ثابت دارد. این استدلال، تضمین رفتار همهٔ مرورگرها نیست.

### بازبینی دستیِ باقی‌مانده

با cache غیرفعال و شبکهٔ کند، hard refresh هر سه صفحه را در هر دو تم و در عرض‌های ۳۲۰ تا ۱۹۲۰+ بررسی کنید: انتخاب فونت/شکست خطوط، ثبات تصاویر و هدر، مقصد لنگرها، focus و فضای نوار رزرو. مسیرهای رفت‌وبرگشت Home/About/Services را برای fallback درست هر صفحه بازبینی کنید. پس از اتصال auth در فاز ۷، همین بررسی را با نشست واردشده و مهمان تکرار کنید؛ در حال حاضر نشست واقعی وجود ندارد. هیچ ادعای اجرای این بررسی‌ها یا اندازه‌گیری CLS/Core Web Vitals نداریم.

آخرین بررسی‌های مجاز: TypeScript، ESLint و build مستقل از DB موفق؛ audit صفر آسیب‌پذیری. هیچ تست، مرورگر، اتصال پایگاه‌داده، handler زنده یا ابزار SEO اجرا نشده است.


## اجزای پایهٔ تأییدشده

Calendar، Chart و دیگر primitiveهای لازم فاز ۲ حفظ شده‌اند، اما نمونه‌های نمایشی آن‌ها حذف شده‌اند و در Home مونت نمی‌شوند. نیازمندی‌های بسته‌ها و استثنای محدود تقویم تغییر نکرده‌اند. نمایش فرم آزمایشی و messageSchema مخصوص آن نیز حذف شده است؛ Home فرم ارسال اطلاعات ندارد. شِل، عکس‌ها، اسلایدر و primitiveهای موردنیاز صفحه از پایهٔ مشترک استفاده می‌کنند. ثبت فعلی شامل **۲۶ مرز Client** (دو ماژول context) است؛ پنج مرز اختصاصی نمایش موقت حذف شدند.

## محتوای Home و بازبینی

- دادهٔ تایپ‌شدهٔ Home در `src/content/home.ts` و خدمات مشترک در `src/content/services.ts`، بخش‌های سروری در `components/sections/home` و کارت‌های تکرارشونده در `components/shared` هستند. slugها لاتین و یکتا هستند، اما مسیرهای جزئیات هنوز ساخته نشده‌اند.
- فقط Hero و دعوت پایانی عکس تمام‌عرض دارند؛ بخش‌های دیگر SectionSurface با سطح‌های متفاوت و عکس داخل کارت هستند. نسخهٔ موبایل عکس‌های تمام‌عرض از فایل crop جدا استفاده می‌کند. همهٔ نوشته‌ها، فلش‌ها، تاریخ/عددهای نمایشی و سلسله‌مراتب عمل‌ها فارسی/RTL هستند.
- CTA اصلی در Hero، بعد از خدمات، دعوت پایانی و نوار ثابت موبایل است. عمل‌های دیدن مطالب/آشنایی با من آرام‌ترند. هیچ ادعای تکمیل رزرو یا نمایش زمان واقعی وجود ندارد.
- متن آموزشی فعلی توصیهٔ تشخیصی یا وعدهٔ نتیجه نیست. schema Article/Course به موضوع‌های منتشرنشده اضافه نشده و schema نظر نمونه نداریم. Home breadcrumb ساختگی ندارد؛ breadcrumb واقعی About/Services در فاز ۴ اضافه شده است.
- در مرورگرِ خودتان عرض‌های ۳۲۰ تا ۱۹۲۰+، دو تم، هدر/نوار رزرو، حاشیهٔ امن، portrait crop، carousel swipe/keyboard/pause و FAQ focus را بازبینی کنید. cache-disabled/throttled hard refresh همچنان لازم است؛ در این محیط هیچ‌کدام اجرا نشده‌اند.
